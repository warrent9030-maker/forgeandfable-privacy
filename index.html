Forge & Fable privacy information

Last updated: 16 August 2026

Forge & Fable is a local-first Android application. It does not operate a central Forge & Fable user-account backend, and the project does not require an account for the core library.

Information kept on the device

The app stores the library and its metadata, reading and listening progress, bookmarks and highlights, collections, listening history, playback preferences, download state, and other settings in the app’s local Room database. Local imported files and app-managed downloads are stored in the app’s private storage. Listening and reading history is retained locally so that progress, resume, statistics, and history features work across app sessions.

The Kindle/Send-to-Kindle feature may store the Kindle email address entered in Settings locally. It is used only when the user explicitly starts an export. The read-aloud voice and speed chosen in Settings are stored locally as well.

Optional network services

Forge & Fable is not entirely offline. When a feature is used, it may communicate directly from the device with services such as:

  • TorBox and Real-Debrid, when the user connects their own account with those providers for streaming or downloads;
  • Audible catalogue endpoints and the Audnexus service (api.audnex.us) for audiobook search and metadata;
  • Open Library and Google Books for book metadata and cover images;
  • OPDS catalogues that the user adds, such as a Calibre, Kavita, or COPS server on their own network or on the internet;
  • custom API sources that the user defines.

Those services receive the network information needed to fulfil the request, such as the device’s IP address, request details, search terms, selected identifiers, and any information included in the request by the service. Search terms and metadata requests are sent directly from the device to the service that answers them; there is no Forge & Fable server in between. The services operate under their own privacy policies, terms, retention rules, and security practices. Forge & Fable does not control those services.

Images, catalogue metadata, source results, stream resolution, and downloads may therefore involve third-party network requests, including cover images fetched from the image hosts of the services that returned the results. The app does not add a Forge & Fable analytics, advertising, or telemetry service. When a third-party provider is down, handling stays on the device.

Background catalogue refresh

When the user has added at least one custom API source, Forge & Fable refreshes those sources in the background about every six hours while a network connection is available, and adds any new results to the local library. A refresh sends the same kind of request as a search the user starts, to the sources the user configured, and nothing else. With no custom sources added there is nothing to fetch and no request is made.

Read aloud

Read aloud hands book text, a sentence at a time, to the text-to-speech engine installed on the device (for example Speech Services by Google). Forge & Fable makes no network request of its own for this. Some engines and voices synthesise speech online, so for those voices the engine may send the text to its provider under that provider’s policy. Settings → Reading marks which voices need a network connection and recommends offline voices; when no voice is chosen, the app prefers an offline voice where the engine offers one. The audio the engine synthesises is written to the app’s private cache and deleted as each sentence finishes.

Highlight exports

Exporting highlights builds a Markdown document on the device. It leaves the device only when the user shares it with an app they choose or saves it to a location they pick.

Credentials

TorBox and Real-Debrid credentials are kept in Android Keystore-backed encrypted preferences rather than the Room database. They are used to authenticate requests to the corresponding provider.

Custom API source definitions are kept separately from their secrets. API-key, bearer, and basic-auth credentials are moved to an Android Keystore-backed encrypted store. The Room configuration contains only the non-sensitive source definition and an opaque reference. Existing configurations that contain inline credentials are migrated when the app starts; if migration cannot safely complete, the inline value is removed from the persisted configuration and the source is marked as requiring the credential to be entered again. Credentials are not written to application logs.

OPDS catalogue entries are kept in an encrypted preference store as well, because a catalogue address can carry a server key or token in its path. They are used only to fetch from the catalogue the user added.

Home-network catalogues

Release builds of Forge & Fable refuse unencrypted HTTP except for OPDS catalogues on the user’s own network. A plain http:// catalogue is accepted only when its address is a private or local-network address; the app checks the addresses the name resolves to and refuses a public one, so a home-looking name cannot carry a password to the internet in the clear. Catalogues reached over the internet use HTTPS.

Backups and exports

Manual Forge & Fable backups export local library metadata, progress, settings, collections, and related records so they can be restored on another installation. They do not intentionally include:

  • TorBox, Real-Debrid, OPDS, or custom API source credentials;
  • bearer credentials, API keys, passwords, or basic-auth values;
  • signed or access-bearing provider/CDN download and stream URLs;
  • transient multipart downloadUrl values; or
  • local filesystem paths.

Authenticated source definitions may be restored as inactive or unhealthy until their credential is entered again. Backup files are created at a user-selected destination and should still be protected like any other personal export.

Android backup/device-transfer exclusions also exclude the local database, downloads, backup files, the encrypted credential stores, and the queue of catalogue downloads (whose links can carry a catalogue server key).

Kindle sharing

When the user explicitly initiates Send-to-Kindle, Forge & Fable prepares URI-scoped attachments and hands the attachments, Kindle address, and email details to the user’s chosen email application. The email application and email provider then handle the message according to their own policies. Forge & Fable does not send the email silently from a Forge & Fable server.

Deletion and control

The user can remove library items, imported files, downloads, OPDS catalogues, custom API source definitions, and stored provider credentials through the app’s available controls. Android’s app-data clearing and uninstall controls remove local app data according to Android’s behaviour. Third-party services retain or delete information under their own controls and policies.

This page is the public privacy policy for Google Play. For questions or privacy requests, use the support email listed on the Forge & Fable Play Store listing.
